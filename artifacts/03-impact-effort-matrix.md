# Матрица приоритизации Impact/Effort

## Обоснование
Для формирования бэклога фич и учета жестких ограничений по срокам (3 месяца на MVP) использовалась матрица Impact/Effort. В первый релиз вошли задачи с максимальным влиянием на конверсию при минимальных затратах (Quick Wins).

## Таблица приоритетов

| Фича | Impact | Effort | Квадрант | Обоснование |
| :--- | :--- | :--- | :--- | :--- |
| **Гостевой чекаут** | 🟢 Высокое (+8-10 п.п.) | 🟡 Среднее | Big Bets | Лечит 40% отказов, но требует правок бэкенда |
| **Прозрачная доставка** | 🟢 Высокое (+3-5 п.п.) | 🟢 Низкое | Quick Wins | API логистики уже есть, нужно только перенести UI |
| **Включить Apple Pay / СБП** | 🟡 Среднее (+2-3 п.п.) | 🟢 Низкое | Quick Wins | Интеграции уже написаны, нужно просто вывести кнопки |
| **Ускорение оплаты (до 2с)** | 🟢 Высокое (+2-4 п.п.) | 🟡 Среднее | Big Bets | Требует оптимизации React, но критично для мобилок |
| **Idempotency (защита от двойных списаний)** | 🟡 Среднее (Лояльность) | 🟡 Среднее | Quick Wins | Снимает большую боль поддержки и повышает доверие |
| **Мобильная оптимизация (UI/UX)** | 🟢 Высокое (+5-8 п.п.) | 🔴 Высокое | Big Bets | Требует переработки верстки и тестов на iOS/Android |
| **One-page checkout** | 🟢 Высокое (+2-5 п.п.) | 🔴 Высокое | Big Bets | Полная переделка логики шагов |

## Решение по релизам
*   **Релиз 1.0 (MVP):** Гостевой чекаут, Прозрачная доставка, Apple Pay/СБП, Ускорение оплаты, Idempotency.
*   **Релиз 2.0 (Отложено):** Мобильная оптимизация (UI/UX), One-page checkout.
