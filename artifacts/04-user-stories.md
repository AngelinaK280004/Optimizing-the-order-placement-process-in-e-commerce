# User Stories и Acceptance Criteria (Релиз 1.0)

## 1. Гостевой чекаут (без регистрации) - ФТ
**Как покупатель,**
я хочу оформить заказ без создания пароля и подтверждения email,
чтобы не тратить время и быстрее получить товар.

**Acceptance Criteria (Критерии приемки):**
*   **Given** пользователь находится в корзине, **When** он нажимает «Оформить заказ», **Then** система открывает форму чекаута без требования ввода пароля.
*   **Given** пользователь заполнил Email, Имя, Телефон и Адрес, **When** он подтверждает заказ, **Then** система создает заказ и отправляет чек на указанный Email.
*   **Given** пользователь оформил заказ как гость, **Then** в БД сохраняется запись с customer_id = NULL (или создается неактивный аккаунт, который можно активировать позже по ссылке из письма).

## 2. Прозрачная доставка - ФТ
**Как покупатель,**
я хочу видеть сумму заказа и доставки,
чтобы принять решение о покупке.

**Acceptance Criteria:**
*   **Given** сумма корзины превышает порог бесплатной доставки, **When** пользователь открывает корзину, **Then** система отображает «Бесплатная доставка».
*   **Given** пользователь находится на заполнении данных для заказа, **When** он выбирает вид доставки, **Then** система просчитывает и выдает сумму доставки.
*   **Given** пользователь находится на заполнении данных для заказа, **When** все поля заполнены, **Then** система отображает общую сумму заказа, стоимость товаров и доставки по отдельности.

## 3. Включить Apple Pay / СБП - ФТ
**Как покупатель,**
я хочу иметь возможность выбора способа оплаты,
чтобы не вводить данные вручную.

**Acceptance Criteria:**
*   **Given** пользователь нажимает на кнопку Apple Pay, **When** открывается системное окно, **Then** данные карты и адрес подтягиваются автоматически из Apple Wallet.
*   **Given** пользователь выбирает СБП, **When** он нажимает «Оплатить», **Then** генерируется QR-код для оплаты через банковское приложение.

## 4. One-page checkout - ФТ (Релиз 2.0)
**Как покупатель,**
я хочу вводить все данные для оформления заказа в одном месте,
чтобы сократить время взаимодействия с системой.

**Acceptance Criteria:**
*   **Given** пользователь находится в корзине, **When** он нажимает «Оформить заказ», **Then** система предоставляет единую форму ввода данных.
*   **Given** пользователь заполняет данные для оформления заказа, **When** он вводит невалидные данные, **Then** система в режиме реального времени подсвечивает неверно заполненные поля с причинами ошибок.
*   **Given** пользователь ввел невалидные данные, **When** он нажимает кнопку «Оплатить заказ», **Then** система не дает сделать этот переход и выдает ошибку.
