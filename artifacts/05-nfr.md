# Нефункциональные требования (NFR)

Для критических технических узлов были сформулированы NFR, чтобы обеспечить стабильность работы системы и высокий уровень UX.

## 1. Idempotency (защита от двойных списаний)
**Требование:** Все запросы на создание платежа должны использовать Idempotency-Key.
**Acceptance Criteria:**
*   **Given** пользователь дважды нажал кнопку «Оплатить» (или произошел сбой сети и фронтенд отправил повторный запрос), **When** бэкенд получает второй запрос с тем же Idempotency-Key, **Then** система не списывает деньги повторно, а возвращает результат первого (успешного) запроса.
*   **Given** двойное списание произошло по вине шлюза, **When** система обрабатывает Webhook о втором платеже, **Then** она логирует инцидент (Error Log) и отправляет уведомление в службу поддержки для ручного возврата средств.

## 2. Ускорение оплаты (с 4с до 2с)
**Требование:** Время загрузки страницы ввода платежных данных (LCP) не должно превышать 2 секунды.
**Acceptance Criteria:**
*   **Given** пользователь на мобильном устройстве в сети 4G, **When** он переходит на шаг оплаты, **Then** интерактивные элементы (поля ввода карты) должны быть доступны для взаимодействия не позднее чем через 2000 мс.
*   **Given** страница оплаты загружается, **Then** скрипты Stripe/платежного шлюза должны загружаться асинхронно (prefetch), не блокируя рендеринг интерфейса.

## 3. Оптимизация (UI/UX моб.версия) - Релиз 2.0
**Требование:** Интерфейс мобильной версии сайта должен соответствовать стандартам эргономики (Apple HIG и Google Material Design): шрифт в полях ввода должен быть не менее 16px, а зоны нажатия интерактивных элементов (кнопок) — не менее 48x48px.
**Acceptance Criteria:**
*   **Given** пользователь открывает форму оформления заказа на мобильном устройстве (iOS), **When** он кликает на поле ввода (Email, адрес, карта), **Then** интерфейс не должен автоматически масштабироваться (зумить), так как размер шрифта в поле составляет не менее 16px.
*   **Given** пользователь находится на странице оплаты с мобильного устройства, **When** он нажимает на кнопку «Оплатить заказ», **Then** зона клика (touch target) должна быть не менее 48x48 пикселей, чтобы исключить случайные промахи и повысить удобство использования.
